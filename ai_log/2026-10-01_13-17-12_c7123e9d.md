1. Comprehension

Hotspot is a new question type, hotspot. It needs no database migration. The author picks an image (a T8 image ID) and places a target point with an inner and an outer ring. Each player taps one point on a canvas on their phone and then presses Submit. The server measures how far the tap is from the target and scores it in bands:
- Inside the inner ring: full points, counted as correct.
- Inside the outer ring: points_value × partialFraction, not counted as correct.
- Outside both: 0.

Coordinates and distance:
- Tap and target positions are stored as fractions of the image's width and height (0 to 1).
- Distance is measured in units of the image's longer side, so the rings are true circles on screen.
- That calculation needs the image's width ÷ height. The editor saves it into config as aspectRatio when the image loads. This only stays correct because T8 promises the bytes under an image ID never change (rule C1).
- One function, game_service.hotspot_band, decides the band. Scoring, the answer counts, both question summaries and the HTML report all call it.

Who sees what:
- During the question, the host screen shows only the image and the answered count.
- At results, the host gets every tap with its band. Each player gets the target and both radii, and draws their own tap.

Export and import: a game with a hotspot question exports as a version 2 bundle. The image bytes are embedded in the file, and each question points to its image with a label like img1 instead of an image ID. Version 1 bundles import exactly as before.

Staging: stage A can be built now. Stage B waits on T4 phase 2, stage C waits on T8, and stage D is Vincent's admin port. The spec also lists what T8 must provide (rules C1–C8).
